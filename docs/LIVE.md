# 大厅与对局

[English](en/LIVE.md)

本文件是切法合同，不是 OCP 的第二套资源。形状仍以 `schema/ocp.v1.schema.json` 为准，HTTP 语义仍以 `docs/SPEC.md` 为准。对局帧写在 `docs/MATCH.md`，不进入 schema。

## 结论

提取公共身份。不要平行再做一份低延迟版的频道、讨论、链接、修订。成熟联机后端的公共做法是：慢接口留在请求-响应，对局状态留在单独的内存进程。不是把同一套 JSON 资源换一种传输再写一遍。

## 成熟后端的切法（对照，不引入其产品）

对照公开架构：Nakama、Photon Realtime、Epic Online Services 的会话接口。

- 账号、存储、群组、大厅名单走请求-响应。
- 权威对局的状态只活在某一进程的内存里：按节拍收输入、校验、再广播。人走光或终局后丢掉，不写成存储对象。
- 匹配或组队成功只交出比赛编号或连接地址，客户端再连对局进程。
- 载荷是操作码加短二进制，并标明这次可不可丢。可靠消息堵住时，移动仍应能过去（独立序号）。
- 大厅聊天和对局同步不是同一条流。专用服务器把连接地址写进会话；客户端先加入会话，再拿这个地址去连游戏进程。

三家重合的交接物：**身份、房间号、短时许可、连接地址**。重合的对局模型：**内存、按节拍、操作码、可靠与可丢分开、结束即弃**。

## 落到本仓库

```text
客户端 ── HTTP /v1 ──► 现有提供方（频道、讨论、链接、分享、修订、入场）
     └── 数据报帧 ──► 对局进程（内存、调用方 reduce、独立序号）
              ▲
              └── 入场：POST .../admissions 签发的短时凭证 + 连接地址
```

### HTTP（OCP）

对应大厅和文档。新增只有入场，没有坐标、操作码、节拍：

| 现有资源 | 在联机里的位置 |
| --- | --- |
| 频道 | 大厅、队伍、房间名单 |
| 讨论 | 要留下的聊天。不传坐标 |
| 分享 | 给人打开的邀请页。不是对局入场证 |
| 修订与 `store.json` | 文档历史。不对局中状态 |
| 链接 `target_url` | 可指向对局进程地址，本身不含入场许可 |
| 入场 | `capabilities.live` 打开后签发；见 SPEC §8.7 |

对局进行中，客户端**保持** HTTP 会话，用来改房间和留聊天。不要学「进对局就断开大厅」：文档频道在对局期间还要用。

### 对局进程（`@open-channel/match`）

对应权威比赛 / 游戏进程：

- 单独进程。状态在内存。不占用参考服务端写 `store.json` 的那把锁。
- 调用方传入 `reduce` 与 `encode`。进程校验凭证、按固定节拍收集输入、调用 `reduce`、广播快照。
- 帧：带头频道 id、参与者、序号、种类。种类只有 `join`、`input`、`event`、`snapshot`。
- 至少两类独立序号：可丢的输入；必须到达的关键事件。可靠包堵住时，本拍的输入仍进入 `reduce`。
- 人走光或终局后丢掉内存。要留战绩，再由 HTTP 写一条讨论或改一次频道正文。不要把每个节拍写成修订。

细则与组帧见 `docs/MATCH.md`。

### 公共身份

- 频道 id：房间仍是现有频道。
- 参与者：现有 actor。谁能进，以 HTTP 侧的成员和令牌为准。
- 短时入场凭证：`POST /v1/channels/{id}/admissions`。绑定频道、参与者、过期时间。签名票只出现一次。

入场凭证**不得**复用分享 token 或授权 `gr_`。分享给人打开页面，寿命长，权限是查看或留言。授权是频道上的 HTTP 权限。入场凭证给对局进程，寿命约 60 秒。

## 传输

帧按数据报语义定义，承载可换：

- 原生客户端用 UDP（`MatchHost.address`）。
- 浏览器没有裸 UDP：本仓对局进程提供 **WebSocket 二进制入口**（`MatchHost.wsAddress`），解码后进同一 `reduce`。接受「全部变成可靠有序」的代价。
- 更接近可丢数据报时，第三方可把同一帧放到 WebRTC 不可靠数据通道；本仓不实现 WebRTC。
- 这不是 OCP 的能力，也不把 WebSocket / WebRTC 写进 `/v1`。入场仍是 `POST .../admissions`，`url` 由提供方配置为 `udp://` 或 `ws://`。

本仓参考实现同时听 UDP 与 WebSocket；走动例子面向浏览器，把 `liveUrl` 配成 `wsAddress`。UDP 地址仍在进程日志里，供原生客户端对接。

## 禁止（薄路径）

- 平行一份「同样资源、换成 UDP」的 OCP
- 讨论当输入流，或 `ext` 里高频改坐标
- 修订当对局快照（每个节拍一条 `rev_`）
- 分享 token 或授权令牌当对局入场证
- 给 `GET/PATCH /v1/channels` 加 tick 或二进制正文
- 把操作码、节拍、序号写进 `ocp.v1.schema.json`
- 非权威的客户端互转发作为本仓参考模型（参考模型是权威进程：服务器校验再广播）
- 从 `examples/walk` 把格子移动抄进内核或协议

## 明确不照搬

匹配池、区域目录、服务器舰队、中继转发是下一层产品，不是本协议缺的字段。本仓不实现完整游戏服务器。
