# 大厅与对局

本文件是切法合同，不是 OCP 的第二套资源。形状仍以 `schema/ocp.v1.schema.json` 为准，HTTP 语义仍以 `docs/SPEC.md` 为准。对局帧不进入 schema。

## 结论

提取公共身份。不要平行再做一份低延迟版的频道、讨论、链接、修订。成熟联机后端的公共做法是：慢接口留在请求-响应，对局状态留在单独的内存进程。不是把同一套 JSON 资源换一种传输再写一遍。

## 成熟后端的切法（对照，不引入其产品）

对照公开架构：Nakama、Photon Realtime、Epic Online Services 的会话接口。

- 账号、存储、群组、大厅名单走请求-响应。
- 权威对局的状态只活在某一进程的内存里：按节拍收输入、校验、再广播。人走光或终局后丢掉，不写成存储对象。
- 匹配或组队成功只交出比赛编号或连接地址，客户端再连对局进程。
- 载荷是操作码加短二进制，并标明这次可不可丢。可靠消息堵住时，移动仍应能过去（独立序号）。
- 大厅聊天和对局同步不是同一条流。专用服务器把连接地址写进会话；客户端先加入会话，再拿这个地址去连游戏进程。

三家重合的交接物：**身份、房间号、短时许可、连接地址**。重合的对局模型：**内存、按节拍、操作码、可靠与可丢分开、结束即弃**。

## 落到本仓库

```text
客户端 ── HTTP /v1 ──► 现有提供方（频道、讨论、链接、分享、修订）
     └── 数据报帧 ──► 对局进程（内存、操作码、独立序号）
              ▲
              └── 入场：HTTP 签发的短时凭证 + 连接地址
```

### HTTP（现有 OCP）

对应大厅和文档，不改成节拍：

| 现有资源 | 在联机里的位置 |
| --- | --- |
| 频道 | 大厅、队伍、房间名单 |
| 讨论 | 要留下的聊天。不传坐标 |
| 分享 | 给人打开的邀请页。不是对局入场证 |
| 修订与 `store.json` | 文档历史。不对局中状态 |
| 链接 `target_url` | 可指向对局进程地址，本身不含入场许可 |

对局进行中，客户端**保持** HTTP 会话，用来改房间和留聊天。不要学「进对局就断开大厅」：文档频道在对局期间还要用。

### 对局进程（本仓尚未实现）

对应权威比赛 / 游戏进程：

- 单独进程。状态在内存。不占用参考服务端写 `store.json` 的那把锁。
- 帧：操作码 + 短二进制，带头频道 id、参与者、序号。
- 至少两类独立序号：可丢的状态或输入；必须到达的关键事件（开局、终局、生成物）。关键事件不得和可丢帧挤在同一序号上。
- 人走光或终局后丢掉内存。要留战绩，再由 HTTP 写一条讨论或改一次频道正文。不要把每个节拍写成修订。

### 公共身份（仅此三样）

- 频道 id：房间仍是现有频道。
- 参与者：现有 actor。谁能进，以 HTTP 侧的成员和令牌为准。
- 短时入场凭证：由 HTTP 签发（路由尚未进 SPEC），低延迟通道校验。绑定频道、参与者、过期时间。用完即废。

入场凭证**不得**复用分享 token。分享给人打开页面，寿命长，权限是查看或留言。入场凭证给对局进程，寿命以秒计。

## 传输

帧按数据报定义，不先把协议钉死成某一种套接字：

- 原生客户端用 UDP。
- 浏览器没有裸 UDP 时，同一帧放到 WebRTC 的不可靠数据通道。
- WebSocket 只作为退化承载体，并接受「全部变成可靠有序」的代价。这不是 OCP 的能力，也不把 WebSocket 写进 `/v1`。

## 禁止（薄路径）

- 平行一份「同样资源、换成 UDP」的 OCP
- 讨论当输入流，或 `ext` 里高频改坐标
- 修订当对局快照（每个节拍一条 `rev_`）
- 分享 token 当对局入场证
- 给 `GET/PATCH /v1/channels` 加 tick 或二进制正文
- 把操作码、节拍、序号写进 `ocp.v1.schema.json`
- 非权威的客户端互转发作为本仓参考模型（参考模型是权威进程：服务器校验再广播）

## 明确不照搬

匹配池、区域目录、服务器舰队、中继转发是下一层产品，不是本协议缺的字段。本仓不实现完整游戏服务器。

## 以后若做成 HTTP 路由

只增加「签发入场凭证并返回连接地址」。那是协议变更，必须同时改 SPEC、schema、两份 SDK 和测试。帧格式与内存对局另写说明，单独进程跑。
